# Руководство по «Котику»

[На главную страницу проекта](../README.md)

## Мини-приложение

Интерфейс: React, TypeScript, Vite и CSS. API и собранные файлы обслуживает
`aiohttp` в том же процессе, что бот и напоминания, на `127.0.0.1:8003`.
Сервер запускается, когда задана переменная `WEBAPP_URL` с публичным HTTPS-адресом.
Открыть «Котик» можно через [Telegram-бота](https://t.me/easy_task_manager_bot). Адрес мини-приложения — [kotik.pavelmarchik.ru](https://kotik.pavelmarchik.ru).

Сборка интерфейса из корня клонированного репозитория:

```bash
cd web
npm ci
npm run build
```

После сборки `web/dist` должен быть рядом с `src`. Каталог сборки не хранится
в Git. Для разработки `npm run dev` проксирует `/api` на локальный сервер.
Бот получает окружение штатным способом; приложение не исполняет `.env` как код.

API принимает подписанный Telegram `initData` через заголовок
`X-Telegram-Init-Data`. Подпись, срок действия и принадлежность пользователя
семье проверяются на сервере. Удалять участников может создатель семьи.
Обычный браузер без Telegram не получает семейные данные.

## Первый запуск

Создайте своего бота в [BotFather](https://t.me/BotFather) и получите токен. В терминале установите Python-зависимости проекта:

```bash
git clone https://github.com/rottenrust/etm-bot.git
cd etm-bot
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install -e .
```

Для запуска в Bash или Zsh выполните команды ниже. После первой команды вставьте токен и нажмите Enter — символы при вводе скрыты.

```bash
read -rs BOT_TOKEN
export BOT_TOKEN
python -m easy_task_manager.main
```

В Telegram отправьте своему боту `/start`. Для нового семейного списка достаточно токена. При первом запуске бот сам создаст файлы для задач, списков, участников и напоминаний. Остальные параметры описаны в [.env.example](../.env.example).

## Повторный запуск

Откройте терминал в каталоге `etm-bot`, выполните `source .venv/bin/activate` и запустите бота командами из блока выше. Чтобы остановить его, нажмите `Ctrl+C`.

## Семейный доступ

Бот работает через личные сообщения. Для текущей семьи можно оставить
`FAMILY_MEMBERS`: при запуске бот добавит этих пользователей в семью `default`,
а существующие задачи из `data/tasks.json` останутся в старом списке.
Формат переменной:

```bash
export FAMILY_MEMBERS="123456789:User,987654321:Partner"
```

Айди нужен для доступа и отправки уведомлений, имя отображается в семейных
уведомлениях о действиях с задачами.

Для публичного режима `FAMILY_MEMBERS` не обязателен. Новый пользователь при
`/start` выбирает кнопками:

- `Создать семью` — бот создает отдельный пустой семейный список.
- `Присоединиться` — бот просит код приглашения.

Участник семьи может нажать `Семья` → `Пригласить`, получить одноразовый код и
отправить его другому человеку. Если бот сможет определить свой username, вместе
с кодом он покажет ссылку вида `https://t.me/<bot>?start=<code>`.

Для новых участников бот сохраняет Telegram username как имя в семейных
уведомлениях. Если username не задан, используется имя из профиля. Уже
сохраненные имена текущих участников не меняются автоматически.

Когда новый участник присоединяется к семье, остальные получают уведомление.
Создатель семьи может открыть `Семья` → `Участники` и удалить другого участника:
удаленный пользователь и оставшиеся участники получат уведомление.

Пользователь может состоять только в одной семье. Код приглашения одноразовый:
после успешного присоединения нужен новый код для следующего человека.

В меню `Семья` можно удалить семейный список. Бот сначала просит подтверждение,
а после подтверждения удаляет участников, приглашения и все дела этой семьи.
Для семьи `default` удаление сохраняется и после перезапуска: бот не восстановит
ее автоматически из `FAMILY_MEMBERS`.

## Меню Telegram

При запуске бот регистрирует системное меню Telegram:

- `/menu` — открыть главное меню с inline-кнопками.
- `/add` — добавить дело.
- `/lists` — открыть списки дел.
- `/family` — открыть семейное меню.
- `/help` — показать краткую помощь.

Команды нужны как быстрые входы из кнопки `Меню` в Telegram. Основное управление
остается через inline-кнопки внутри сообщений бота.

## Большие списки задач

Готовые тематические списки: `Общий`, `Покупки`, `Дом`, `Дача`, `Отпуск`,
`Здоровье`, `Работа`. Для уже созданной задачи можно открыть карточку задачи и
нажать `Изменить список`, чтобы перенести ее в другой список.

Если дел стало много, бот показывает список страницами по 6 задач. Под текущей
страницей доступны кнопки только для видимых задач, а между страницами можно
переключаться стрелками `←` и `→`.

Задачи в списке группируются по дате дедлайна. Сначала идут ближайшие дедлайны
по дате и времени, затем задачи без дедлайна по возрастанию номера.

Пример семейного сценария: Маша открывает `Списки`, видит первую страницу дел,
нажимает `→`, выбирает задачу на второй странице, а кнопка `Назад` возвращает ее
на ту же страницу списка.

## Локальные данные

Задачи хранятся в локальном файле `data/tasks.json`. Тематические списки
хранятся в `data/task_lists.json`. Семьи, участники и коды приглашения хранятся
в `data/families.json`. Состояние ежедневных напоминаний хранится в
`data/reminder_state.json`, чтобы бот не дублировал уведомления 9:00 и 18:00
после перезапуска. Эти файлы содержат личные данные и Telegram chat ID, поэтому
они не должны попадать в публичный репозиторий.

## Дедлайны и время

Все даты дедлайнов, время дедлайнов и напоминания бот считает по московскому
часовому поясу `Europe/Moscow`.

## Повторяющиеся задачи

Задачу с дедлайном можно сделать регулярной: каждый день, каждую неделю или
каждый месяц. При добавлении задачи бот спросит про повтор после выбора дедлайна
и времени. Для уже созданной задачи можно открыть карточку и нажать
`Повторять`, чтобы включить, изменить или удалить повторение.

Когда регулярная задача завершена кнопкой `Сделал`, бот скрывает текущий
экземпляр из активных списков и создает следующий с тем же текстом, списком и
временем дедлайна. Если повторение больше не нужно, нажмите `Повторять` →
`Не повторять`, и после завершения задача исчезнет как обычная.

## Проверка тестов

Тесты запускаются только на временных данных, включая файлы семей и состояния
напоминаний. Не используйте файлы работающего бота:

```bash
kotik_test_dir="$(mktemp -d)"
TASKS_FILE="$kotik_test_dir/tasks.json" \
TASK_LISTS_FILE="$kotik_test_dir/task_lists.json" \
FAMILIES_FILE="$kotik_test_dir/families.json" \
REMINDER_STATE_FILE="$kotik_test_dir/reminder_state.json" \
BOT_TOKEN= FAMILY_MEMBERS= WEBAPP_URL= \
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p "test_*_unittest.py"
```

Проверка интерфейса из каталога `web` после установки зависимостей командой `npm ci`:

```bash
npm run build
npx playwright install chromium
npm run test:visual
```

Для браузерных проверок нужен Chromium Playwright. Тесты сохраняют снимки
21 состояния интерфейса, проверяют действия с делами, обновление общих
данных, узкий экран, компьютер, прокрутку и ввод. По снимкам проверьте, что заголовки и подписи помещаются на экране.

Для изменений пользовательского сценария проверь его вручную в Telegram на двух участниках семьи: действие, результат для обоих и возврат к списку. Не загружай реальные семейные данные в тесты или репозиторий.

В Telegram также проверь фактическое открытие мини-приложения, экранную клавиатуру,
приглашение второго участника, уведомления и доступ после удаления участника.
Подмена Telegram SDK или API в браузерном тесте не заменяет эту проверку.
